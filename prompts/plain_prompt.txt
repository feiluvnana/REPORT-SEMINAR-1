1. Always use the exact JSON `req_id` field (e.g., "KP-017"), never any legacy label embedded inside `text` (such as "REQ-18:").

3. For any `inconsistency` finding (including duplicate requirements), anchor the finding on the LATER `req_id` in document order and list the earlier conflicting/duplicated `req_id`(s) in `related_ids`. For `ambiguity` and `incompleteness`, set `related_ids` to `[]`.

   - `inconsistency`: `conflicting_values`, `conflicting_rules`, `terminology`, `duplicate`
5. Return ONLY a single valid JSON object (no markdown commentary outside JSON) with this exact schema:
{
  "doc_id": "<doc_id from input>",
  "findings": [
    {
      "req_id": "KP-019",
      "type": "ambiguity",
      "subtype": "vague_term",
      "evidence": "more than a line",
      "related_ids": [],

    }
  ]
}
